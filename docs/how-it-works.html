How it works

What happens between a folder of raw frames and a finished picture, and why. Each step is explained in plain terms first, then the method it uses and where it comes from. The advanced page lists the features and their flags; this page is about the ideas underneath.

Why stacking works

A single 10-second frame of a faint galaxy is mostly noise. Every frame records the same galaxy, but the noise in each frame is different and random. Add frames together and the galaxy adds up in proportion to the number of frames, while random noise adds up only as its square root. Stack N frames and the signal-to-noise ratio improves by about √N: 100 frames are ten times cleaner than one.

Signal and noiseSNR ∝ √N

The noise comes from three places: the random arrival of photons (shot noise, which grows with the brightness itself), the sensor's read-out electronics, and heat in the sensor (dark current). Stacking beats down all three, but only the random parts. Anything that is the same in every frame, such as a hot pixel, a dust shadow or a gradient from a streetlight, stacks up just like the galaxy does. That is what calibration and background extraction are for.

Linear dataRAWSTACK=True

A pixel's value in a raw frame is proportional to the light that fell on it. That property, linearity, is what makes measurement possible: double the starlight, double the number. OriginStack keeps the stack linear in the FITS file it saves, and does every measurement, from colour calibration to photometry, on that linear stack. Only the preview image is stretched for viewing, because the eye needs faint things brightened far more than bright ones.

The pipeline, end to end

A run has four phases. The first three produce the linear stack; the fourth turns it into a picture. Each phase can be checkpointed, so a change to a later setting does not repeat the earlier work.

Phase 1: process and score

Every frame is loaded, calibrated, cleaned of hot pixels, demosaiced into colour, white-balanced and measured: star count, star width, sharpness and noise. Frames run in parallel, one process per CPU core. Clearly bad frames are dropped here.

Phase 2: register

Each frame's offset, rotation and scale relative to a reference frame is measured to a fraction of a pixel, then checked by re-measuring star positions after alignment.

Phase 3: warp and combine

Frames are resampled onto the reference grid, cropped to the area every frame covers, and combined pixel by pixel with outlier rejection, then recombined by spatial frequency (proper coaddition).

Phase 4: finish

Gradients are removed, colour noise and luminance noise reduced, stars tightened, contrast enhanced, and the image stretched for display. This phase reads the linear stack and never changes it.

Calibration: removing what every frame shares

Stacking cannot remove a defect that sits in the same place in every frame. Calibration subtracts and divides those defects out first, using frames taken for the purpose.

Bias, darks and flatsmaster frames

A bias frame is a zero-length exposure: the sensor's electronic offset. A dark is an exposure with the light blocked, recording the heat signal that builds up over the exposure. A flat is an exposure of an even light source, recording how the optics and dust dim parts of the field (vignetting and dust shadows). Each light is corrected as (light − bias − dark) ÷ normalised flat.

Many calibration frames are combined into one master per type with a median, so the masters themselves carry little noise. Darks are chosen to match the lights' sensor temperature, since dark current roughly doubles every 6 °C, and scaled when their exposure time differs.

Hot pixels, without eating starson by default

A hot pixel is one far brighter than its neighbours. So is the centre of a small, sharp star, which is the trap: on the Origin a star can be only about two pixels wide in each colour plane. OriginStack works on the raw sensor mosaic and flags a pixel that stands far above the median of its own colour plane, then keeps it if the adjacent pixels of the other colours are also raised. A hot pixel leaves its neighbours alone; starlight spills into them.

Before this rule, the hot-pixel step was clipping the peak of almost every star in every frame. Fixing it made stacked stars about 14% narrower on one session.

Robust statisticsmedian, MAD

Astronomical images are full of outliers: stars, satellites, cosmic rays. A mean and standard deviation are dragged around by them; a median and the median absolute deviation (MAD) are not. Almost every threshold in the pipeline is set in units of a robust noise estimate like this, so it adapts to each frame instead of using a fixed number.

From colour mosaic to colour image

A colour camera sensor sees only brightness. To get colour, each pixel sits under a red, green or blue filter in a repeating 2×2 pattern (the Bayer pattern, usually RGGB): half the pixels are green, a quarter red and a quarter blue. Every pixel is missing two of its three colours, and demosaicing fills them in.

Ratio Corrected Demosaicing--debayer-method rcd default

The simplest fill averages the nearest pixels of the missing colour, which blurs edges and star profiles. RCD, by Luis Sanz Rodríguez and used by Siril, RawTherapee and darktable, first decides at each pixel whether detail runs more horizontally or vertically, and interpolates along it. It then fills colour from ratios between channels rather than raw differences, since the ratio of red to green changes much more slowly across a star than the brightness does.

Against known ground truth it has lower error than the Malvar method used before on every synthetic scene tested, and on real Origin stacks it left 7 to 15% less noise per colour.

The two greenssession-constant equalisation

The two green pixels in each 2×2 block are slightly different in sensitivity, which leaves a faint checkerboard. The difference is a property of the sensor, so it is measured once per session from a handful of frames and removed from every frame in the same pass that writes the demosaiced image.

White balance--white-balance

Each frame's channels are scaled so the sky background comes out neutral. This is only a starting point: true star colour is fitted later against a catalogue (see colour calibration).

Finding and measuring stars

Stars are the reference points for nearly everything: frame quality, alignment, the sharpness model, colour calibration and the sky position. So the pipeline needs to find them reliably in noisy frames.

The matched filterstar detection

The best linear way to find a signal of known shape in random noise is to correlate the image with that shape. A star is a small round blur, so the frame (minus its local background) is convolved with a small Gaussian the size of a star, and peaks well above the local noise are stars. The background and noise are estimated on a coarse grid of cells, so a nebula or gradient does not throw off the threshold.

Validated against the established SEP and DAOStarFinder detectors on real frames, with sub-pixel centroids after a refinement pass, and about twice as fast as SEP.

Star widthFWHM

The full width at half maximum of a star's profile is the usual measure of sharpness: the seeing that night, focus and tracking all show up in it. Each frame's FWHM, star count, signal-to-noise and a sharpness score feed into which frames are kept and how much each counts.

Comparing sharpness fairlyshared stars

A stack's average FWHM depends on which stars it was measured on. When OriginStack compares two stacks, its own or another program's, it measures the same stars in both. An earlier comparison that did not was wrong by more than the difference it claimed.

Registration: lining frames up

Between frames the telescope drifts, and on an alt-az mount like the Origin the field also slowly rotates around the target as it crosses the sky. Before frames can be combined, each one's offset and rotation must be known to a small fraction of a pixel.

A coarse shift firstpyramid + phase correlation

The offset between two images shows up as a peak in their cross-correlation. Computing that with Fourier transforms (phase correlation) finds the shift for the whole image at once. OriginStack does it coarse to fine: on a half-resolution copy to find the rough offset, then at full resolution only in a small window around it, then to sub-pixel precision by fitting a curve through the peak.

Then rotation, from star patternsstar matching + RANSAC

A shift alone cannot describe a rotated field. The stars of each frame are matched to those of the reference, and a rotation plus translation is fitted to the matched pairs. Some matches are always wrong, so the fit uses RANSAC: fit to a few random pairs, count how many other pairs agree, repeat, and keep the fit that most pairs agree with. The final fit uses all the agreeing pairs with the closed-form least-squares solution of Umeyama. The random sampling uses a fixed seed, so the same frames always give the same result.

When the rotation is unknownblind pattern match

For frames where the simple shift came out as nonsense, and for stacks from different nights, nothing is known about the rotation. The trick: the distance between two stars does not change when the field rotates or shifts. Pairs of stars with matching distances in both images are candidate matches; candidates that agree on one rotation angle are the real ones. Because both images come from the same camera, the scale is exactly 1, which removes one unknown.

On a real Fireworks Galaxy session, 34 of 148 frames needed this rescue. Before, they were stacked in the wrong place.

Checking the answerresidual gate

After alignment, star positions are measured again on a sample of frames. A frame whose stars still land too far from the reference is dropped. The limit adapts to the session, so one wrongly set threshold cannot throw away a whole night. The reference frame itself is chosen from the middle of the session in time, which keeps the area common to all frames as large as possible.

ResamplingLanczos-3

Moving an image by a fraction of a pixel means computing new pixel values between the old ones. OriginStack uses a Lanczos-3 kernel, a windowed sinc that keeps fine detail far better than bilinear interpolation. Each frame is warped once, with the shift and rotation combined into a single resampling step, so it is never blurred twice.

Combining: one value from many

Once aligned, every pixel position has one value from each frame. Most of those values are good. A few are not: a satellite crossed, a cosmic ray hit, a plane's light passed through. Combining is deciding which values to trust and how to average them.

Mean versus medianthe trade

The mean of good data has the lowest noise, but one satellite trail drags it up. The median ignores the trail but is about 25% noisier on clean data. Rejection gets the best of both: find the outliers, drop them, average the rest.

Sigma clipping--stack-method sigma_clip 15+ frames

For each pixel, take the median of the frames' values and their spread (from the MAD), reject any value more than 3 spreads away, and repeat up to three times. Then average what remains, weighted by each frame's quality. With fewer than 15 frames a sigma estimate is unreliable, so the default switches to a percentile clip, which simply drops the highest and lowest values.

Also available: winsorized clipping, a generalised extreme-studentized-deviate test (ESD), linear-fit clipping, inverse-variance weighting and a wavelet-domain combine. See the advanced page.

Weights from quality, region by regionpatch weighting

A frame that is sharp in one corner and soft in another, because of a gust of wind or a tilt, is scored in patches, and counts for more where it is sharp.

Common cropno black borders

A rotated and shifted frame no longer fills the whole grid. The stack is cropped to the area every frame covers, so the edge is not a ragged mix of fewer frames. With --full-field the stack is extended to everything any frame covered instead.

Proper coaddition: weighting by detail

A weighted average gives each frame one weight for everything in it. But a soft frame and a sharp frame are equally good at recording the smooth glow of a nebula, and very different at recording a small star. Proper image coaddition (Zackay and Ofek, 2017) gives each frame a separate weight for every scale of detail.

The ideaon by default --no-proper-coadd

Any image can be split into spatial frequencies, from the broad background to the finest detail, with a Fourier transform. Blur weakens the high frequencies; how much is described by the frame's point-spread function (PSF), the shape a point of light takes in that frame. Proper coaddition weights each frame at each frequency by how much of that frequency its PSF passed, divided by its noise. Sharp frames dominate the fine detail; every frame still contributes to the smooth parts.

R̂ = Σj (Fj / σj2) P̂j* M̂j  /  √( Σj (Fj2 / σj2) |P̂j|2 )

M is each frame, P its PSF, F its transparency, σ its background noise; the hat means the Fourier transform. The result is mathematically guaranteed to be at least as sharp as a weighted mean of the same frames, and keeps total flux unchanged.

Measured, not assumedper-frame PSF

Each frame's PSF is measured by fitting an elliptical Moffat profile (a star shape with realistic wide wings) jointly to about 30 bright, isolated, unsaturated stars. Its transparency comes from those stars' brightness in a fixed aperture, and its noise from the sky. Outliers such as satellite trails are removed first against the normal stack.

On three real sessions: stars 1.3 to 2.7% narrower than the plain stack, with equal or lower noise.

Where it is on the sky, and its true colour

Plate solvingWCS built in

A world coordinate system (WCS) maps every pixel to a right ascension and declination. To find it, OriginStack projects catalogue stars from Gaia onto a flat plane around a guess at the field centre (from the Origin's own session file or the FITS header), at the expected pixel scale, and matches the pattern to the brightest stars in the image with the same rotation-free distance matching used for registration. A match is refined to a full affine fit. Catalogue tiles are cached on your computer, so a field solved once solves offline afterwards.

The Origin's own solve describes the session's first frame, not the stack. Carrying it through the registration and refining it took the median error on a real stack from 63 pixels to 0.24.

Colour calibration against Gaiaon by default

The Gaia space telescope measured the colour of over a billion stars, as a difference between its blue and red magnitudes (BP−RP). OriginStack measures the instrumental colour of the isolated, unsaturated stars in the linear stack, fits it against their Gaia colours with a robust (Theil-Sen) line, and scales the channels so a star with the Sun's colour (BP−RP = 0.82) comes out white. Scaling channels keeps the stack linear. In a dense or reddened field where the stars span too narrow a range, it queries fainter stars, and if the fit is too scattered it declines rather than guess.

Photometry--photometry

Star brightness is measured in a circular aperture with partial pixels counted by area, the sky level from a surrounding ring with outliers rejected, and converted to magnitudes with a zero point fitted against Gaia, corrected for the thickness of atmosphere at that altitude. The noise model uses the camera's gain measured from your own frames; the gain the Origin writes in its headers is about five times too high.

Finishing the image

The linear stack is accurate but looks almost black. Phase 4 makes it look like the object. The order matters: each step assumes the earlier ones have run.

Background extractionDBE default

Light pollution, moonlight and vignetting leave a smooth glow across the frame that is not part of the sky. Dynamic background extraction lays a grid of 64-pixel patches over the image, discards patches that contain stars or the object, takes a robust level from the rest, and fits a smooth surface through them with a local regression that rejects outlying patches. That surface is subtracted. When a large galaxy covers the middle of the frame, the surface under it is filled from a radial model instead of stretched across from the edges.

Colour noisechroma NR

The eye is far more forgiving of blurred colour than blurred brightness. Colour noise in the sky is smoothed with a masked blur: stars and the object are left out of the blur, so their colour cannot bleed into the sky, and they keep their original colour exactly. The sky is centred on zero at this point, so negative values are kept, not clipped.

Wavelet noise reduction--denoiser wavelet default

A wavelet transform splits the image into detail at different scales and orientations. Noise spreads thinly over all the small-scale coefficients; real detail concentrates in a few large ones. BayesShrink sets a threshold per band from that band's noise and signal, shrinking small coefficients toward zero. OriginStack adds a structure map: where the image has a coherent direction, such as a filament or a spiral arm, the threshold is lowered so that structure survives.

Deconvolution--deconvolve opt-in

If the blur is known, it can be partly undone. Richardson-Lucy iterates toward the sharp image that, blurred by the measured PSF, best reproduces the data. It also amplifies noise and rings around bright stars, so stars are masked and it is off by default.

Star reduction and local contrastshrink_stars multiscale contrast

Star reduction narrows each star's profile while keeping its peak brightness and colour, so stars do not crowd out the object. Local contrast enhancement boosts mid-scale detail on the object, measured against the sky noise at each scale, so it sharpens structure without amplifying noise.

The stretch--stretch ghs default

Finally, the linear values are mapped to display brightness. The generalised hyperbolic stretch brightens faint levels steeply while compressing highlights gently, with the black point set from the measured sky noise. With --stretch-color preserve the curve is applied to brightness only and colour ratios are kept (Lupton et al., 2004), so bright stars keep their colour instead of turning white.

Speed and memory

Never more frames than fitframe store

A 500-frame Origin session is tens of gigabytes once demosaiced and aligned. Before creating each large array, OriginStack checks the memory actually available, keeps a fifth of the machine's RAM free, and puts the array in memory only if it fits; otherwise it goes to a temporary file mapped into memory. Where it lives never changes the result: both placements are tested to give bit-identical stacks.

Rust kernels with a safety netastro_native

The hot loops (calibration, demosaicing, star detection, warping, the combines, coaddition, denoising) are written in Rust and run multi-threaded. Every one has a plain NumPy version of the same algorithm, and a test checks the two agree, in most cases bit for bit. A kernel is only written after measuring that NumPy is actually wasting time there.

Reproduciblesame input, same output

Every random choice is seeded, so stacking the same frames twice gives the same image. Each run saves its effective settings; checkpoints are tied to the files and settings they came from, so a stale one is never reused.

How we check it

An image that looks better is not necessarily more correct. Every step on this page was measured before it became a default, and several ideas that looked good did not survive measurement; they are listed on the advanced page.

Ground truth

Synthetic scenes with known stars and nebulae let each step's error be measured exactly: demosaicing, drizzle, denoising and the colour pipeline were all chosen this way.

Real sessions, same stars

On real Origin data there is no truth to compare against, so changes are measured as star width on the same stars and noise matched at equal sharpness, against the previous version and against Siril. tools/bench_vs_siril.py repeats the comparison on your own frames.

The data checks itself--noise-validate

Stacking the odd and even frames separately and comparing them gives the true noise in the stack and shows which structure is real: it appears in both halves.
