Other cameras

OriginStack was built for the Celestron Origin and is tested mostly on its data, but nothing in the stacking itself is specific to it. Frames from other one-shot-colour cameras, dedicated astro cameras and DSLRs alike, go through the same pipeline. This page says what works, how to set up the folder, and where the limits are today.

File formats

Every format below loads through the same path, so they can be mixed in one folder. The installers include everything needed; from source, RAW and TIFF need pip install rawpy tifffile.

SER.serVideo from FireCapture, SharpCap and similar. Each frame in the file becomes one light frame.

Setting up the folder

Put the light frames and any calibration frames in one folder and choose that folder, or keep a calibration library elsewhere and point --cal-dir at it: the best-matching frames of each type are picked from it by ISO, sensor temperature, exposure, filter and frame size. Subfolders of a single night are not searched; a folder whose subfolders each hold a night is stacked as several sessions.

How frames are sorted

A file whose name contains dark, flat or bias is that kind of calibration frame; so is a file whose IMAGETYP header is exactly DARK, FLAT or BIAS, and a zero-length exposure is a bias. Everything else is a light.

Some capture programs write IMAGETYP as Dark Frame or Flat Field, which is not recognised yet. Keep the frame type in the file names (most programs do by default) and it works either way.

Darks

Darks are matched to the lights by sensor temperature and exposure time, and scaled when the exposure differs. A library of darks at several temperatures can be modelled instead (--dark-temp-model).

Flats

Flats are normalised and divided out. With no flats, --flat-from-lights estimates one from the lights themselves; it is approximate.

Leave out

Dark flats: there is no separate dark-flat step, and a file named darkflat would be taken as a dark. Use bias frames for the flats instead. Earlier OriginStack outputs in the folder are recognised and skipped.

Colour sensors and the Bayer pattern

A one-shot-colour sensor records a Bayer mosaic, and the debayering step needs to know which corner of each 2×2 block is red.

Where the pattern comes from

The BAYERPAT (or COLORTYP) header for FITS, the file itself for RAW, the colour ID for SER. With none of these it assumes RGGB.

A wrong pattern is caught

Some software writes a pattern that is flipped top to bottom against the pixel data; the Origin does. Each session's declared pattern is checked against the mosaic itself, and the flipped version is used when the two green sites disagree by more than a real sensor could.

Override it.json sidecar

A single-channel TIFF, or any frame with a missing or wrong header, takes its pattern from a JSON file with the same name next to it, for example light_001.json containing {"bayerPattern": "GRBG"}.

What needs an Origin

The session fileinfo.json

The Origin writes the target, the site location and a first sky solution into each session folder. Other cameras get these from the headers above instead, so a capture program that writes a good header gives the same results.

The camera profile

The Origin's camera gain is measured and built in. For other cameras, photometry measures the gain from pairs of bias and flat frames when the folder has them, and otherwise falls back to the header's GAIN/EGAIN.

Tuned defaults

The automatic settings were tuned on Origin data: 10 to 30 second subs at about 1.5 arcseconds per pixel. They adapt to the frames, but very different data, such as long DSLR exposures at a wide field, may be better served by choosing the target type yourself.

Limits today

Monochrome cameras

Single-channel FITS, TIFF and RAW frames are always treated as a colour mosaic, so frames from a mono camera come out wrong. Mono SER and XISF files are the exception: they are read as greyscale. Narrowband or LRGB channels stacked elsewhere can still be combined with the combine subcommand.

Planetary imaging

SER files are stacked with the deep-sky pipeline and the planetary preset: whole-frame alignment and quality selection, no multi-point alignment. For the Moon and planets at high magnification, a dedicated lucky-imaging stacker will do better.

Less testing

Nearly all of the measurements on this site are on Origin data. Other cameras are expected to work, but have had far less use. If something goes wrong, open an issue with the log and, if you can, a few sample frames.
