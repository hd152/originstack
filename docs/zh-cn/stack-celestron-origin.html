如何在电脑上叠加 Celestron Origin 图像

Origin 一边拍摄一边叠加，但它也保留了拍摄的每一张原始帧。在电脑上以正确的校准和对齐重新叠加这些帧，能得到比望远镜保存的图像更锐利、更干净的结果。本指南使用 OriginStack 完成这一过程，它免费，并在你自己的电脑上运行。

Celestron Origin 会话文件夹里有什么

每次拍摄会话都有自己的文件夹，以目标和开始时间命名，例如 Black_Eye_Galaxy_2026-03-14_21-20-36。将整个文件夹复制到电脑上，内容保持原样即可。OriginStack 会自行识别每个文件。

亮场Light0001.fits ...

每次曝光一个 FITS 文件。这些是原始传感器数据，仍处于相机的彩色马赛克格式，也就是要叠加的数据。

校准帧bias, dark, flat

偏置场、暗场和平场（如果会话中有的话）。它们记录了传感器的偏置、热信号和热像素，以及光学系统的暗角。OriginStack 用它们生成主校准帧，并用其校正每一张亮场。没有校准帧的会话也能叠加，只是跳过这一校正。

会话信息info.json

由 Origin 写入：目标名称、传感器的颜色排列、你的 GPS 位置，以及望远镜所指向的天区。OriginStack 用它来命名目标、为其选择设置，并将叠加结果定位到天空中。

望远镜自带的叠加FinalStackedMaster.tiff

Origin 在会话期间生成的图像。OriginStack 会忽略它，因此它永远不会被当作另一帧叠加进去。

分步叠加

1. 安装 OriginStackWindows, macOS, Linux

在 Windows 上，从最新版本下载安装文件并运行。安装程序尚未进行代码签名，因此 SmartScreen 可能会发出警告：请选择“更多信息”，然后选择“仍要运行”。在 Mac 上，从同一页面下载 Apple 芯片或 Intel 版 zip，并将 OriginStack 拖入“应用程序”；首次启动需要额外批准一次，具体说明与 Linux 步骤一起列在首页。无需账号，也无需 Python。

2. 选择会话文件夹

打开应用并选择你复制的文件夹。它会统计帧数，并从 info.json 中读取目标名称。

3. 说明你拍了什么

选择星系、星云、星团、星场或彗星，或保持“自动检测”。应用会根据会话建议一个。选择“完整质量”，或选择“快速预览”进行较快的检查。

4. 按“开始”

各帧会经过校准、评分、对齐（包括 Origin 这类地平式支架产生的视场缓慢旋转）、带离群值剔除的叠加，以及成品处理：处理梯度、颜色和噪声，并将结果拉伸以便观看。在一台较新的 8 核台式机上，约一百帧的会话需要一两分钟。预览会随着每一步实时更新。

5. 使用结果

输出留空时，叠加结果会保存在会话文件夹旁边，绝不覆盖之前的结果。你会得到一张用于查看和分享的 JPEG，以及一个保持线性的 FITS 文件，可在其他软件中做进一步处理，或日后与另一晚的数据合并。

更喜欢命令行？同样的运行是 python originstack.py -d Black_Eye_Galaxy_2026-03-14_21-20-36 -o black_eye.fits。

同一目标的多个夜晚

把每晚的会话文件夹放进同一个上级文件夹，然后选择这个上级文件夹。由于 Origin 跟踪目标时视场会旋转，各晚的画面很少能完全对齐。OriginStack 会先读取每个会话的元数据，然后选择能保留更多画面的方式：要么合并所有帧，要么每晚单独叠加，再用不受旋转影响的星点匹配拼合。要把今晚的帧加入已有的叠加结果，请使用 --merge。详情见高级页面。

为什么要重新叠加，而不是直接使用 FinalStackedMaster.tiff

在四个 Origin 会话上，使用相同的帧，望远镜自带叠加的星点比 OriginStack 宽 3% 到 38%，而噪声相差在几个百分点以内。Origin 的文件确实有一个优势：天空梯度已经被去除。OriginStack 则在成品处理步骤中去除梯度。

完整的测量数据、方法以及与 Siril 和 DeepSkyStacker 的对比见首页。来自同一台望远镜的四个会话样本量很小；tools/bench_vs_origin.py 可以在你自己的帧上重复这一对比。

出现问题时

找不到任何帧

请选择直接存放 Light*.fits 文件的文件夹，或存放多个会话文件夹的文件夹，而不是更上一级的文件夹。

识别的目标类型不对

请自己选择卡片，不要使用“自动检测”。在命令行中，传入 --target-type。

没有网络连接

叠加可以离线进行。在应用中勾选“离线”，或传入 --offline，OriginStack 就不会发出任何网络请求。

其他问题

请在 GitHub 上提交issue，并附上应用左下方面板中的日志。
