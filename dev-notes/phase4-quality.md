### Phase 4 image quality (2026-10)
`tools/bench_phase4.py` scores the *delivered* image -- Phase 4 + the display stretch as float (`io_fits.render_preview_float`) -- on linear stacks via the real `--from-stack` path (`pipeline.prepare_linear_for_phase4`, each stack's `_config.toml`) plus a synthetic galaxy with known truth: same-star FWHM ratio Phase 4 output / linear, star colour index (display vs linear, Spearman + Theil-Sen), hue error on bright pixels, display sky noise, faint-signal CNR, dark rings, large-scale chroma mottle, flatness, and with a WCS the display colour of a G2V star from Gaia (cached as `<stem>_gaia.json`). `--variant NAME="flags"`, `@key=value` for config-only settings. Inputs used: Sunflower, Whirlpool (low SNR), Crab, Trifid, Veil, M24 + synthetic (`bench_phase4_data/`, git-ignored). Findings and changes, old -> new:
- **Per-channel stretch whitened stars and shifted hue** (hue error 3-7.5 deg on bright pixels, star colour rank correlation with the linear stack 0.51-0.91). `colour_preserving_stretch` applies the curve to luminance and scales RGB by T(n)/n (Lupton 2004); chroma faded in over 3 sky sigma above black; over-range pixels divided by their largest channel (desaturating toward grey turned every core at the white point white). Hue error -> 0.01-0.07 deg, colour correlation 0.80-0.98, chroma mottle down 26-66% (Trifid 11%). `--stretch-color channel` restores the old curve. **2026-10: the default went back to `channel`** (user preference for the per-channel look); `--stretch-color preserve` keeps the measurements above. The desktop app's live previews now follow `--stretch-color` too (they had always used `preserve`).
- **Star reduction widened stars**: `reduce_stars` (blend toward a blurred copy) made Sunflower/Whirlpool/synthetic stars 6-18% *wider* than linear. `shrink_stars` removes `(1 - (e/A)^amount)` of each star's smoothed light above an annulus background (never below that background -- removing the smoothed light from a pixel below it fed local contrast a near-zero luminance and three pixels reached 1e12), tapered at 2.5 FWHM: 0.84-0.87 of linear width.
- **Anisotropic diffusion kappa was 30 ADU**: 3 sky sigma on Veil, 0.65 on Crab, 0.3 on Trifid. Now 1.0 x sky sigma. `bench_denoise_quality.py` chain sweep: detail kept 0.95-1.0 at 0.5, 0.80-0.93 at 1.0, 0.62-0.84 at 2.0; display sky noise halves per doubling. Veil's display sky is noisier than before (it had 3 sigma), Crab/Trifid quieter. Old configs' `aniso_kappa` is ignored (the attribute no longer exists).
- **Colour calibration against Gaia is on by default** (`--no-color-calibrate`; hidden `--color-calibrate` kept for old command lines), method `solar` (`color_calibrate.fit_channel_scales_solar`): instrumental B/R, G/R of detected, isolated, unsaturated, SNR>20 Gaia stars fitted against BP-RP (Theil-Sen), scaled so BP-RP 0.82 is white, on the *linear* stack before Phase 4 (`pipeline._colour_calibrate_stack`, also the linear FITS -- per-channel scales keep it linear; COLCAL headers). Phase 4's gray-locus step is skipped when it succeeded. Display G2V colour index: Sunflower -0.078 -> 0.027, Whirlpool -0.099 -> 0.025, Trifid 0.101 -> 0.006, Veil -0.051 -> -0.028; **Crab -0.065 -> -0.190** (its 32-star fit reads -0.09 on a wider star sample and Phase 4's nebula chain moves it ~-0.1 further; not resolved). **Crab, followed up (2026-10):** two separate causes. (1) *The fit:* the brightest-first Gaia query (1200 rows) of this dense, reddened field matched only G 13.1-13.8, and 32 isolated SNR>20 stars, all red, put the solar point (BP-RP 0.82) on an extrapolated, noisy slope: 0.35 against 0.31 from ~1000 stars in four magnitude slices (each slice within 0.03 of the others; aperture size 1.6-2.5 FWHM changes it by 0.001, saturation removal by 0.006). `fit_channel_scales_solar` now runs one deeper query (3000 rows from the faintest G returned) when the usable stars span < 1.5 mag (`_SOLAR_THIN_SLICE_MAG`; only Crab of the six bench stacks triggers it, +12 s), merging stars not already matched (`_merge_gaia_matches`): 65 stars, display G2V -0.113 (bench, colour calibration forced to `solar`). It also declines when the B-R scatter about the fit exceeds 0.2 mag (`_SOLAR_MAX_SCATTER`; real fields 0.05-0.10): the deeper query let M24's star cloud through with 0.36 and a 0.18 slope. (2) *The display:* B's second-moment radius is 7-15% larger than R's on 4 of 5 stacks, so stars have red cores and blue halos -- **a halo in the wings, not a wider core** (followed up the same month: Gaussian-fit core FWHM B/R is 0.96-1.01 in the Crab/Sunflower stacks; in raw Bayer planes of single subs the B core reads 1.18-1.21x and the debayer's luminance-guided interpolation brings it level; the wing excess is already in the raw subs, so it is light, not processing -- Malvar and RCD stacks give the same B/R 1.159/1.152; and B-R centroid offsets in four stacks are 0.00-0.27 px, so the session CA threshold is not hiding a shift); the colour-preserving stretch scales each pixel by T(n)/n, which weights a star's wings over its core, so aperture colours measured on the display come out bluer (Crab -0.12 display vs -0.03 on the Phase 4 output before the stretch; blurring R/G to B's width moved the display to +0.07). Galaxy presets do not show it because `shrink_stars` makes the channel widths equal. **Tried and dropped:** per-star profile matching (each channel's star excess replaced by the luminance profile times that channel's flux, inside 2.5 FWHM, >3 sigma pixels only): Crab -0.113 -> -0.088, Veil -0.021 -> +0.008, but star-colour correlation with Gaia fell on Trifid 0.904 -> 0.851 (structured nebulosity inside a 7.5 px-FWHM star's disk) and Sunflower 0.877 -> 0.859 (0.76 with a 10-20 sigma star threshold). Note for `bench_phase4.py`: an old `_config.toml` with `color_calibrate_method = "colorindex"` silently overrides the method of a `--color-calibrate` variant -- pass `--color-calibrate-method solar` too. M24 declines (9 stars at SNR>20). Before Phase 4 the uncalibrated linear stacks are far off (Sunflower +0.50, Crab +0.26); gray-locus was what had been correcting them.
- **Bugs found on the way**: the old `--color-calibrate` measured the *post-processed* image and wrote it into the `RAWSTACK=True` FITS; the `--from-stack` early-step cache was keyed on the file only (now also a strided pixel sample, computed once before the early steps change the array -- recomputing it at save time never matched); `WCS(header)` emits `FITSFixedWarning` and astropy's handler iterates `sys.modules`, which raised under a concurrent import and the fail-soft callers reported "no usable WCS" (`photometry_core._celestial_wcs` silences those warnings).
- **DBE under a large exclusion region** (`background._fill_exclusion_radial`): a real Pinwheel (M33) stack came out as a saturated red slab with dark holes either side. The linear stack had colour-dependent vignetting peaking at the frame centre (R-G 780 ADU higher in the middle than at r = 1500 px, despite flats), `--galaxy-mode`'s ellipse covered 34% of the frame right over it, and DBE's locally-linear fit could only carry the rim inward: R 6-9x G next to the galaxy, over-subtracted rim. When the exclusion is >= 10% of the frame (`_RADIAL_FILL_MIN_FRAC`), the surface under it (feathered over 2 patches) is a robust fit of plane + a r^2 + b r^4 about the frame centre to all accepted patches, level-matched to the local model at the rim. A free quadratic through the ring was tried first and bent the wrong way (unconstrained in the middle) -- and both first attempts treated DBE's `coords` as pixels: they are normalised (y/H, x/W). Pinwheel: core R/G 1.14, disk ~1.0, mottle 26.4 -> 4.9. Gated because on Sunflower/Whirlpool (~5% exclusions) it made mottle ~10% worse.
- **Multiscale local contrast amplified sky noise and skipped small objects** (`denoising.multiscale_local_contrast`). Its mask came from the per-pixel luminance against `_estimate_sky_sigma`, an adjacent-pixel estimate that reads far too low after the wavelet denoiser has correlated neighbours, so the mask switched on over the sky at every upward noise excursion; and the highlight cap / detail clip were whole-frame percentiles, which on a galaxy covering 2.5-3% of the frame sit *below* the galaxy, so the mask was zero on the object. Now: mask from a 2 px-smoothed luminance in its own noise units (robust sigma of its departure from a 40 px blur, fainter half of the pixels), cap and clip at the 99th percentile of the above-sky pixels, each detail layer cored against its own sky sigma (no boost under 1 sigma, full from 3). Display, vs local contrast off (sky noise / 2-12 px structure on the object): Sunflower 1.77x/0.96x -> 1.06x/1.30x, Whirlpool 1.79x/0.97x -> 1.02x/1.29x, Crab 1.18x/1.13x -> 0.72x/1.05x (Crab's brighter core lifts the preview white point, scaling the whole display down; structure per unit sky noise 13.4 off / 12.8 old / 19.6 new). Rings better, star width within +3% of off. Scratch harness: Phase 4 run through `bench_phase4.run_phase4` with the function monkeypatched on `src.postprocess` -- the steps *after* local contrast (edge bands, sky neutralise) must run, so score the real output, not the function's return. `tests/test_local_contrast_noise.py` fails on the old version.
- **Galaxy detail through Phase 4, scored against a second night (2026-10-23).** Phase 4 run on one night of 7 two-night galaxies (Andromeda, Eyes, Fireworks, M101, NGC 891, Pinwheel, Sunflower; 14 directions) with every intermediate saved; the other night registered onto it; per starlet scale (1-16 px), on galaxy pixels with stars masked, the regression of each stage on the other night (structure both show) relative to Phase 4's input, so the other night's PSF cancels. `--deconvolve nn` keeps it (0.93-1.00 at 1-16 px) while cutting noise to 4-36%; local contrast adds 2-12%. **Star reduction looked like it removed 12-25% at 2-16 px -- a measurement artefact:** masking 20 px around every source Phase 4 detects, it keeps 1.000 at 1-4 px on all five galaxies checked; the remaining 8-16 px "loss" (0.68-0.98) is star wings inside those scales' footprints, i.e. star reduction doing its job. Real but small: a source detected *on* an arm dents the arm within 2.5 FWHM (synthetic: ~80% of a 7 px arm at 2.4 FWHM). A ring-median star model (only the round part of each source reduced, resolved sources skipped) cut that to ~5% but left saturated stars -- flat, wide cores -- unreduced: `bench_phase4` ring on Sculptor/Sunflower 0.44/0.35 -> 1.77/1.73, star width 0.905/0.885 -> 0.928/0.904. Not shipped; a retry must exempt clipped cores from the width test and keep that bench.
- **Background extraction scored between two nights (2026-10-23).** 27 two-night targets, Phase 4 on each night, the other night registered onto it and matched by per-channel *gain only* (an offset or surface fit would remove the error measured); 64 px block medians of the luminance difference, stars masked, with a scaled copy of the target's own shape fitted out (a gain mismatch leaves one), in raw per-pixel sky sigma (both nights' errors together). Raw stacks median 1.44, after DBE 0.34: ~70% of the gradient mismatch removed. <= 0.5 on 17 targets (galaxies, small nebulae, clusters); 0.6-2.3 on frame-filling nebulosity / reflection nebulae and one cluster edge (NGC 891 0.58, NGC 2244 0.64, Eagle 0.81, Horsehead 0.82, Lagoon 1.06, Hercules 1.59, Pleiades 2.11, Flaming Star 2.30): DBE takes different amounts of the faint outer nebula on each night. Orion (48) and Omega (9.6) are not measurable this way (bright cores differ non-linearly between nights). **DBE settings sweep** on those 8 + 6 controls, DBE re-run on the inputs Phase 4 hands it (captured once per night): patch 32/64/96 (auto-scaled default 47), `DBE_FIT_SIGMA_PATCHES` 1.0-2.5, masked fraction 0.15/0.5, outlier sigma 1.5 all within ~5% of the default on both groups; `DBE_DENSE_FIELD_THRESH` 0.5/0.9 and `use_entropy_weights` off changed nothing at all on these targets; diffuse threshold 0.5-2.0 (default 0.25 on nebulae) "agrees" by removing the nebula (target light kept 0.88 / 0.55 / 0.05 of the default); `--bg-method wavelet` 1.6x worse on the weak group, 2.3x (worst 7.2x) on the controls. Per target, without losing target light, the best setting gains 1-7%, except Hercules (diffuse 2.0: 1.58 -> 1.13 -- a globular cluster has no nebula to protect; one pair, not changed) and Pleiades (wavelet: 2.1 -> 1.4, but wavelet is worse everywhere else). So DBE is at its method's limit on nebula-filled frames, not mistuned; a learned background model is the remaining route, for ~30% of targets.
- **Learned background extraction (2026-10-24): tried, not shipped.** A U-Net at 1/8 resolution (whole-frame receptive field, output smoothed to >= 12 px, numpy forward on `nn_conv3x3`) trained to predict the background of `clean + background` composites: `clean` = DBE's output of 47 sessions, backgrounds = the surfaces DBE removed (`tools/gen_background_bank.py` captures both from Phase 4's real call), flipped/rescaled to the image's noise. Scored with `tools/eval_background_nights.py` on 14 held-out two-night targets (mismatch as above; `kept` = slope of the extracted image's block medians on the raw ones, the guard against removing the nebula on both nights). v1 (backgrounds from all sessions) and v2 (backgrounds only from galaxy/cluster sessions, where DBE's surface is gradient) both **remove faint nebula**: kept Eagle 0.44 -> 0.08, Lagoon 0.45 -> 0.13, Horsehead 0.23 -> 0.03, Crab 0.32 -> 0.11, Flaming Star 0.71 -> 0.29, and mismatch worse on Eagle (0.81 -> 2.30) and Pleiades (2.12 -> 2.88). Better on both counts only on Andromeda (0.50 -> 0.32, kept 0.51 -> 0.89) and NGC 2244 (0.64 -> 0.47). Cause: the training images are DBE outputs, which have already lost every nebula's large smooth component, so the network never sees frame-filling faint nebulosity that must be kept and learns that large and smooth means background. Needs training images whose faint large-scale nebula is known to be real; no public source gives that at Origin's field size (deep surveys subtract their own large-scale backgrounds or avoid the Galactic plane). Do not retry with DBE outputs as the clean images.
- **`--repair-stars` scored (2026-10-27): not for `--auto`.** Held-out Pleiades / Orion / Omega, `--deconvolve nn` with and without it (`tools/bench_phase4.py`). It finds a core only at >= 0.92 of the image's luminance maximum: 24 / 18 / 15 cores, against 46 / 46 / 106 stars saturated by the star remover's per-channel 0.7 test (stacked clip levels vary over the field: 10th percentile of the saturated stars' peaks 0.60-0.82 of the channel maximum). Metrics: dark rings 4.38 -> 4.11 (Pleiades), 1.59 -> 0.98 (Orion), 1.49 -> 1.49 (Omega); linear star-colour rho 0.993 -> 0.975 on the Pleiades, unchanged elsewhere; width, noise, faint contrast, Gaia colour within noise. In the JPEG the repaired stars look the same (crops of the 2nd, 1/3 and 2/3 brightest saturated stars per field): the preview white point clips star cores by design, so a rebuilt peak above it is still white. The repair only changes the linear data; it stays opt-in.
- **The beginner targets' default look (2026-10-27): Orion, Andromeda, Horsehead.** The site's Origin-vs-OriginStack pairs showed these three losing to the Origin's own stack; each re-run on 2.17 (Orion 2025-12-27, Andromeda 2025-09-30, Horsehead 2025-11-07 21-25, default settings).
  - *Andromeda: dark discs around every star on the disk* -- star reduction, not the NN deconvolver (`--skip-step star_reduce` removed them, `deconvolve_nn` did not). `shrink_stars` took `keep = (e/A)**amount` per pixel, so any grain of galaxy light above the ring median inside R counted as wing and lost most of itself. Now the removal follows the star's radial median profile (sub-pixel centre), cut at the first radius where it is < 3x the ring median's error and never rising outward, and each pixel loses at most `min(its smoothed light, 1.5 x profile)`. The radial profile alone left ragged, spiky stars (stars are not round); without the cut a synthetic textured disk still dipped 0.2 sigma (ring medians wander with the texture). `bench_phase4` old -> new: fwhm ratio Sunflower 0.887 -> 0.884, Whirlpool 0.923 -> 0.918, M31 0.704 -> 0.716; ring 0.32 / 0.24 / -0.52 -> 1.04 / 1.31 / 1.51 (a moat gone, a faint halo of ~1 sky noise left on isolated stars); faint CNR +3-5% on the two bench galaxies, M31 -2%; Gaia colour rho -0.01 to -0.02. Nebula stacks unchanged (their presets do not reduce stars).
  - *Orion: a jagged white cut-out core* -- not proper coadd (`--no-proper-coadd` gives the same 0.39 -> 0.95 cliff), not the deconvolver or local contrast (skipping each keeps it; without the deconvolver a black hole appears beside it). The Trapezium region clips in every 20 s sub (~15k px plateau) and the nebula's own profile is that steep (single calibrated subs ramp 0.47 -> 0.95 of peak over ~18 px). The roll-off maps the plateau to 1 and the steep edge just below, so the outline -- set by where subs clipped -- shows. A dome extrapolated into the plateau at the edge slope did not help (still flat white, plus a dark feather line); feathering the plateau's outline in the display, sigma 0.11 x its equivalent radius (8 px on M42), does (`io_fits._feather_clipped_core`, regions >= 2000 px at >= 0.9 of the peak luminance; star cores are a few hundred).
  - *Horsehead: IC 434 subtracted, the horse against black* -- the linear stack has it plainly. DBE's emission mask measures "above sky" from the border, which here is the nebula; 1515 of ~2700 patches were sampled on it. A stiffer surface does not help (bandwidth 4 / 8 / 16 patches, same result -- note: `--from-stack` reuses `<stem>_phase4cache.pkl` across changes to `Config` constants, delete it between such runs). Skipping DBE leaves everything black too (the sky floor then sits on the nebula). Colour separates them: red excess `R - k G` (k = lower-quartile R/G) shows the IC 434 ridge cleanly while Alnitak's glare is neutral. `_halpha_excess_mask` masks excess > p25 + 3 robust sigma (28.9% of the Horsehead frame; at 2 or 1.5 sigma the mask passes 70% and DBE drops to the dense-field mesh, worse). It marks 11-37% of *every* frame (galaxies, M24 35%, Pleiades 11%: light-pollution colour gradients), so it is on only where `--auto` sees an emission nebula (weight >= 0.5, `dbe_halpha_mask`). `bench_phase4` off -> on: Horsehead flatness 54 -> 47, blotch 8.4 -> 7.8, faint CNR 64 -> 69; Trifid flatness 42 -> 32, blotch 4.6 -> 3.7, faint CNR 12.3 -> 10.9; Crab, Veil, Omega, Orion within 2% (Orion CNR +3%).

- **`--stretch object` as the default? No (2026-10-30).** `bench_phase4`, base (`ghs`) vs `--stretch object` on ten stacks (Sunflower, Whirlpool, Sculptor, Omega, Orion, Pleiades, Crab, Trifid, Veil, M24; no pointing anchor, so the object is sought at the frame centre). Identical to `ghs` on five (Sunflower, Omega, Orion, Pleiades, Veil). Changed on five, and on every one the sky got noisier and the colour less faithful: sky noise Whirlpool 0.78 -> 1.92, Sculptor 0.74 -> 1.56, Trifid 2.34 -> 4.32, M24 0.94 -> 1.70, Crab 0.76 -> 1.06 (8-bit units); chroma blotch 1.5-2.2x; star colour rank correlation with the linear stack Whirlpool 0.75 -> 0.59, Sculptor 0.74 -> 0.67, Trifid 0.93 -> 0.81; hue error +0.1 to +0.9 deg; faint-signal CNR down on four (Whirlpool 11.7 -> 10.6, Sculptor 21.3 -> 19.1, M24 15.0 -> 13.9) and +3% on Trifid. The CHANGELOG's "exactly the plain `ghs` stretch on nebulae, clusters and anything that fills the frame" does not hold on these stacks: Crab, Trifid and M24 changed (their runs had no anchor; with a real pointing the object may be found elsewhere). The metrics do not score the brighter object itself, which is what the stretch is for, so it stays an opt-in for small faint galaxies on a clean sky.
